# Изменения

## Следующая версия — не выпущена

- **Каталог стратегий zapret2 в подборе и параллельная проверка.** В «Подборе стратегии» — выбор «Каталог zapret2»: **расширенный** (около 275 стратегий для HTTPS, 2–5 минут) или **полный** (около 3100, 15–30 минут). Это те же функции, позиции разреза и способы испортить фейк, что перебирает blockcheck2 из zapret2 (multisplit, multidisorder, fake с разными блобами и порчей, hostfakesplit, fakedsplit/fakeddisorder, seqovl, перебор TTL). Большой набор проверяется **параллельно**: один отдельный nfqws2 держит 15 стратегий сразу, каждая на своём куске проверочных портов (выбор по метке пакета, `--filter-mark`), — в 10–15 раз быстрее, чем по одной. Итог пачки ненадёжен: провайдер судит по адресу сайта в целом, и соединения пачки влияют друг на друга (на сайте с обрывом на 16 КБ 19 стратегий из 275 «открыли» его в пачке и ни одна — по одной). Поэтому находки перепроверяются по одной, начиная с быстрых, пока не наберётся 8 подтверждённых (отметка «перепроверена», не больше 24 попыток); рабочими считаются только они — и в рекомендации, и в истории подборов. То, что работало раньше, находки пробы обрыва и стратегии сообщества в пачки не попадают: они проверяются по одной и первыми. Из каталога в таблице остаётся только то, что открыло сайт хоть раз; остальное — строкой «не помогли: тайм-аут — N, …».
- **Проба «Обрыв на 16 КБ»** («Проверка сайта → Обрыв на 16 КБ»). Многие провайдеры пропускают начало соединения с зарубежными хостингами и замораживают его после 16–20 КБ (или ещё до ответа сервера). Обычные стратегии тут не помогают, помогает фейк с именем сайта, который провайдер не трогает, — и имя подходит для всей сети хостинга сразу. Проба открывает опорные адреса в крупных сетях (Hetzner, OVH, Linode, Vultr, CDN77, CloudFront, Cloudflare, для сравнения — Selectel) и ваши сайты без обхода, а для сетей с обрывом подбирает имя (ya.ru, vk.com, gosuslugi.ru, ozon.ru, www.google.com) на двух приёмах. Найденное — кнопкой **«Применить для сети»**: список адресов сети по ASN (обновляется сам раз в сутки) и профиль первым, с перезапуском и проверкой. Находкой можно поделиться в базе сообщества — для сети, без имени сайта. Работает отдельный nfqws2 на проверочных соединениях, трафик сети не затрагивается; занимает 2–10 минут.
- **Подбор берёт находки пробы «Обрыв на 16 КБ».** Если проба уже нашла имя для фейка, подбор пробует эту стратегию первой: сначала найденное в сети самого сайта, затем в других сетях. В каталоге и стандартном наборе фейков с именем нет, и без этого на сайте с обрывом подбор честно перебирал сотни стратегий впустую.
- **Служебные файлы переживают отключение питания.** Настройки, история подборов, мониторинг, список снимков и сам конфиг теперь сбрасываются на диск до того, как новый файл встаёт на место старого. Раньше файл, записанный за секунды до отключения света, после включения мог оказаться пустым — так терялась история подборов. Если история всё же не читается, она не затирается молча, а остаётся рядом как `picks.json.bad`.
- **Подбор, диагноз и проба больше не задевают соединения устройств сети.** Проверочные правила ловили соединения по портам источника 40000–40999, а с такими портами ходят и телефоны, и компьютеры на Linux (примерно 3 соединения из 100): пока шла проверка, такое соединение шло мимо основного nfqws2, а в подборе — через проверяемую стратегию. Так же могла «не открыться» и проверка мониторинга, совпавшая с подбором. Теперь правила берут только соединения самого роутера (по адресу, с которого соединение началось), остальное идёт как обычно. Заметным это стало с полным набором каталога: он идёт 20–30 минут, а не две.

## 1.9.0 — 2026-10-07

- **Стратегии сообщества.** Общая база рабочих стратегий по провайдерам — открытый репозиторий [zemidala/nfqws2-strategies](https://github.com/zemidala/nfqws2-strategies). DPI у провайдеров разный, и то, что сработало у абонента вашего провайдера, — лучшее, с чего начать:
  - **подбор** пробует до восьми стратегий из базы для вашего провайдера (галочка «стратегии сообщества», включена), сначала — открывавшие тот же сайт или сайты в той же сети (например, на Hetzner). Автоподбор при поломке — тоже. Применяется только то, что открыло сайт на вашем роутере;
  - **«Поделиться»** у стратегии, открывшей сайт каждый раз (результаты подбора, история подборов), открывает уже заполненную форму на GitHub: провайдер (номер AS), протокол, стратегия и, если оставить, сайт. Отправляете вы сами, нужен аккаунт GitHub. У стратегии из базы, которая сработала и у вас, — **«Подтвердить»**: подтверждения поднимают её для других;
  - присланное проверяет GitHub Action: принимаются только шаги `--lua-desync` без путей к файлам и с результатом «открылся N из N», каждый человек засчитывается один раз;
  - **«Не сработала»** у стратегии из базы, которая у вас не открыла сайт. У каждого человека учитывается последнее, что он сказал; стратегию, которая не сработала у большинства (и хотя бы у двоих), подбор больше не пробует. Стратегии, которые никто не подтверждал больше 60 дней, идут после свежих;
  - страница **«Проверка сайта → Стратегии сообщества»**: всё, что есть в базе для вашего провайдера, с отметками «давно не подтверждалась» и «подбор не пробует», проверкой на выбранном сайте и ссылкой на всю базу на GitHub;
  - база на GitHub читается и без роутера: [список по провайдерам](https://github.com/zemidala/nfqws2-strategies/blob/main/STRATEGIES.md) собирается сам после каждой заявки;
  - если в базе для вашего провайдера ещё пусто, после удачного подбора интерфейс предложит поделиться найденным;
  - роутер скачивает только файл своего провайдера — несколько килобайт при любом размере базы, раз в сутки и только когда подбор или страница его используют;
  - если GitHub не ответил из-за короткого сбоя DNS на роутере, загрузка базы повторяется через 3 секунды.

  Номер AS провайдера определяется у RIPEstat по внешнему адресу (адрес нигде не сохраняется) или вписывается вручную.
- **Метки «новое».** После обновления новые страницы и функции отмечены: в меню — «новое» (в стиле «как в Keenetic» — точка), на вкладках, разделах нижней панели и кнопке «Меню» — точка, внутри страницы — «новое» рядом с самой функцией. Метка пропадает, когда страницу открыли; отметка хранится на роутере, поэтому открыли с телефона — пропала и на компьютере. Сверху — сообщение «Обновлено до…» со списком нового и ссылками, пока его не закроют. Метки видят только обновившиеся (при новой установке новым ничего не считается), и не дольше двух версий. Прежние постоянные метки «новое» у страниц версии 1.5 убраны.
- Окна «Для чата» и «Вставить чужой профиль» были без отступов по краям.

## 1.8.0 — 2026-10-07

- **Широкий экран занят целиком.** Раньше содержимое упиралось в 1320 пикселей (в «Вокруг сайта» — в 1240 по центру), и на мониторе шире Full HD справа оставалась пустая полоса. Теперь ширина раскладывается по смыслу страницы, а строки не растягиваются:
  - **«Обзор»** — карточек становится больше в ряду: «Плитки» и «Кладка» до 5–7 колонок, «Панель» — по 400 пикселей на ячейку; в «Кратко» строка состояния и «Сайт не открывается?» рядом, подробности — в несколько колонок;
  - **«Списки»** — записи в две-три колонки; **«Мониторинг»** — сайты в две-три колонки;
  - **формы, проверки и таблицы** («Основное», «Параметры запуска», «Уведомления», «Автоподбор», «Подбор стратегии», «Диагноз», «Трассировка», истории, копии, «Оформление», «О программе», карточка сайта) — справа колонка состояния: сервис с кнопками, замечания, мониторинг, резервные копии. Подсказки к полям — справа от поля, а не под ним;
  - на экранах до ~1600 пикселей всё как раньше.
- **Резервные копии на NAS.** «Система → Резервные копии → Копии на NAS»: роутер сам отправляет каждый новый снимок по ssh на NAS или любое устройство с ssh. Там хранятся все снимки, на роутере — несколько последних (по умолчанию 5) и закреплённые; снимок удаляется с роутера только после того, как дошёл. Снимки с NAS видны в общем списке — их можно скачать, сравнить и восстановить. Ключ роутера создаётся кнопкой, интерфейс показывает одну команду для NAS: она кладёт маленький скрипт приёма и разрешает ключ только для него — этим ключом нельзя ни войти в систему, ни удалить или перезаписать старые снимки, ни выйти из своей папки. Если NAS был выключен, неотправленное уйдёт со следующим снимком или ночью. Закрытый ключ в снимки и скачиваемые архивы не попадает. Проверено на Synology (DSM 7) с OpenWrt; на Keenetic (OpenSSH из Entware) не проверялось.
- **Обновление кнопкой на Keenetic могло не запуститься**: интерфейс запускал установку через `setsid`, а он на Keenetic есть только с busybox из Entware. Окно при этом бесконечно показывало «Обновляю…», помогала только команда из консоли. Теперь установка запускается и без `setsid`, а если запуск всё же не состоялся — окно через 20 секунд говорит об этом и показывает команду.
- **Журнал nfqws2 больше не съедает память роутера.** На OpenWrt `/var/log` лежит в оперативной памяти, а отладочный журнал за несколько часов вырастает до сотен мегабайт. Теперь: замечание в «Проблемах» от 20 МБ (ошибка — от 100 МБ или когда свободной памяти меньше 15%) с кнопками «Очистить» и «Выключить отладку»; в «Журнале» у каждого файла — сколько он занимает и «Очистить»; в «Основном» у галочки «Отладочный журнал» — текущий размер. Раз в 10 минут журнал больше 50 МБ подрезается до последнего 1 МБ. Очистка идёт на месте — nfqws2 продолжает писать, перезапуск не нужен.
- **«Журнал» не открывался, если отладочный журнал nfqws2 вырос** (на сотни мегабайт): программа читала файл целиком и упиралась в память PHP. Теперь читается только хвост.

## 1.5.4 — 2026-10-05

- **Проверка конфига: `tls_mod` на блобе, который не TLS.** Частая запись из чужих конфигов — `fake:blob=0x00000000:…:tls_mod=…`: подставлять SNI в четыре нулевых байта некуда, nfqws2 отправляет фейк как есть и на каждое соединение пишет в журнал «cannot apply tls mod». Теперь проверка это замечает и предлагает «Убрать tls_mod» — работа стратегии от этого не меняется. Блоб проверяется по первым байтам: заданный через `0x…`, из файла или встроенный.
- Проверка обновлений: неудачная попытка (GitHub недоступен) запоминалась на 12 часов, и всё это время интерфейс не видел новую версию. Теперь — на 10 минут. `nfqws-ui update --check` заставляет интерфейс перепроверить.

## 1.5.2 — 2026-10-05

- **Уведомления в Telegram через туннель или прокси.** На странице «Уведомления» — «Отправлять»: как обычно, через выбранный интерфейс (WireGuard, AmneziaWG, OpenVPN) или через SOCKS5/HTTP-прокси. Нужно там, где Telegram закрыт у провайдера. Если проверочное сообщение не ушло, причина пишется словами: нет ответа, нет соединения, интерфейс не найден. Пароль прокси в интерфейсе не показывается (#12).
- **Подбор: «добавить сайт в список».** Если сработала стратегия, которая уже стоит в одном из профилей, а сайт до него не доходит только потому, что его нет в списке профиля, подбор первым делом предлагает добавить сайт в этот список. Новый профиль не создаётся, перезапуск не нужен. После добавления интерфейс проверяет, через какой профиль сайт пошёл на самом деле (#14).
- **Автоподбор делает то же самое.** Если найденная стратегия уже стоит в профиле, сайт добавляется в его список — без перезапуска nfqws2. Роутер проверяет сайт: не открылся — запись убирается, и стратегия применяется отдельным профилем, как раньше (#14).
- Установщик на Keenetic с mipsel писал «Entware (mips)»: архитектура бралась у ядра. Теперь — у opkg, как и в «Отчёте для помощи». На саму установку это не влияло (#13).

## 1.5.0 — 2026-10-04

Интерфейс перестроен, чтобы вместить новые функции: вместо трёх вкладок — страницы в боковом меню. Адреса прежних страниц не изменились.

- **Компоновки.** Три на выбор в «Оформлении»: боковое меню (по умолчанию), вкладки, вокруг сайта. В верхней панели слева — сам интерфейс, справа — nfqws2: версия, состояние, перезапуск и остановка.
- **Обзор** стал отдельной страницей с четырьмя видами: группы, плитки, кладка, панель.
- **Диагноз блокировки.** Роутер по шагам выясняет, чем заблокирован сайт: подмена DNS (сравнение с защищённым DNS Яндекса и Google), блокировка по IP, по имени сайта, заморозка «16–20 КБ» — и говорит, поможет ли подбор стратегии.
- **Уточнение в подборе.** Если ни одна стратегия не открывает сайт каждый раз, подбор сам перебирает у лучшей способ порчи фейка, число фейков (до 20) и подставное имя. Порядок перебора зависит от того, как рвётся соединение без обхода. Подбор не стартует, если имя сайта не находится или адрес не отвечает.
- **История подборов.** Что и когда работало для каждого сайта; «Проверить снова» — быстрый подбор только по уже работавшему. Работавшие стратегии подбор пробует первыми.
- **Автоподбор при поломке.** Сайт из мониторинга перестал открываться — роутер сам подбирает стратегию и предлагает её или, если разрешить, применяет отдельным профилем только для этого сайта, с проверкой и откатом. По умолчанию выключен.
- **Причина, когда nfqws2 не работает:** что именно не так и что с этим сделать.
- **Предупреждение о других обходчиках**, работающих одновременно.
- **Обмен профилями:** «Для чата» у профиля и «Вставить чужой» с проверкой и пробным прогоном на сайте.
- **Отчёт для помощи:** текст без секретов для вопроса в чате или issue.
- **Список по ASN:** адреса сети хостинга по номеру AS или по имени сайта, с ежедневным обновлением.
- «Списки» и «Профили» приведены к одному виду; Telegram-уведомления вынесены на отдельную страницу.
- Интерфейс замечает, что браузер показывает старую версию страницы из кеша, и предлагает перезагрузить. Номер сборки виден в «О программе».
- Значок приложения — знак ZD.
- После обновления один раз показывается подсказка, куда переехали разделы и как вернуть вкладки.

- Команда `nfqws-ui-setup update [--check] [vX.Y.Z] [--force]` и `version`. Короткое имя команды — `nfqws-ui`, например `nfqws-ui update`.

- Ссылка на репозиторий в шапке.
- Подсветка журналов (системный журнал, файлы журналов, трассировка, журнал обновления): время, уровень, процесс, пути, файлы, параметры, адреса, ошибки и предупреждения.

- «Параметры запуска»: добавление из списков — lua-скрипты из `lua/`, файлы блобов из `blobs/`, общие параметры nfqws2 из его справки. В списках только то, чего ещё нет. Параметры, которые ломают запуск или задаются init-скриптом, не предлагаются.
- «Проверить сайт»: кнопка «Проверить →» вместо лупы, результат можно свернуть.
- Выравнивание иконок и подписей, строк форм и таблиц. Узкая колонка третьего оформления и шапка на средних ширинах экрана больше не вылезают за край.
